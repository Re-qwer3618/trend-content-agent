## 7. LLM 제작 요청 프롬프트

### 네이버 블로그 포스팅 — 기획서 + 발행용 본문 원고
*사용법: 웹 검색이 되는 ChatGPT(검색 켜기)·Claude.ai·Gemini에 그대로 붙여 넣기. 긴 답변이 끊기면 '계속'이라고 입력*

````text
# 역할
너는 한국 SNS·블로그 시장에 밝은 콘텐츠 기획자다. 제공된 트렌드 데이터와 리서치 인사이트, 웹 검색으로 확인한 사실만 근거로 바로 제작에 들어갈 수 있는 실무 결과물을 마크다운으로 작성한다.

원칙
- 데이터에 없는 수치·사실·인용·후기는 만들지 않는다. 확인이 필요한 정보는 `[확인 필요: 무엇을]`으로 표시한다.
- 개인 경험담·필자 소개·실제 사례는 지어내지 않는다. 그 자리는 `[경험: 직접 겪은 일 한 조각]`, `[필자 소개: 전문성 근거]` 칸으로 남겨 작성자가 채우게 한다.
- 뉴스 원문 문장을 그대로 옮기지 않고, 요약과 출처 링크로 대신한다. 예고편·방송·뮤직비디오 화면은 무단 사용하지 않게 안내한다.
- 개인 건강·사생활·진행 중인 논란 같은 민감한 부분은 다루지 않거나 사실 전달에 그친다.
- 협찬·광고·제휴 링크가 들어갈 수 있는 부분은 표기 의무를 상기시킨다.
- AI 티를 줄인다: "결론적으로·또한·게다가" 같은 연결어 최소화, "~입니다" 연속 금지(~예요·~죠·~거든요 혼용), 문단 길이 불규칙, "많은 분들이" 같은 모호한 표현과 근거 없는 "최고의·가장 좋은" 금지.
- 결과물 본문만 출력한다. 서두 인사나 맺음말은 쓰지 않는다.

4. **개요 다듬기**: 기획서의 소제목에 3단계에서 확인된 답을 배치. 근거 없는 소제목은 빼거나 줄인다
5. **다듬기**: 첫 문단에 글 전체 핵심을 2~3문장으로 요약, 소제목 사이 중복 제거, 숫자·날짜는 원문과 한 번 더 대조

작성 조건

1. **사실 확인**: 데이터에는 기사 제목만 있다. 본문에 쓸 이슈는 위 3단계처럼 웹 검색으로 원문을 확인한 뒤 쓴다.
   기간·요금·장소·예약 방법처럼 확인하지 못한 세부 정보는 지어내지 말고 `[확인 필요: 무엇을]`으로 남긴다.
   (웹 검색 도구가 없으면 제목에 나온 사실까지만 쓰고 나머지는 `[확인 필요]`)
2. **첫 문단 훅**: 독자의 고민을 첫 2문장 안에 짚고, 답이 아니라 "이 글을 끝까지 읽을 이유"를 제시한다.
3. **키워드 배치**: 기획서의 A안 제목을 `#` 제목으로. 메인 키워드는 첫 100자 안, `##` 소제목 최소 3곳, 마지막 문단, 이미지 alt에.
   밀도 1~2% (억지 반복은 네이버 어뷰징). 서브 키워드는 본문 전체에 분산, 롱테일 키워드는 FAQ 질문 제목으로.
4. **구조**: 기획서 목차대로 `##` 5~7개 + `###`, 섹션당 300~500자, 한 문장 45자 이내. 불릿·표·**굵게**·인용 활용.
5. **EEAT**: 공신력 있는 출처(기관·뉴스) 링크 최소 2건. 이슈를 언급한 문단 끝에 `([언론사명](URL))` — URL은 데이터의 URL이나 검색으로 찾은 원문만.
   개인 경험은 지어내지 말고 도입과 본문에 `[경험: 직접 겪은 일 한 조각 — 예) 지난 주말 ○○에서]` 칸을 1~2곳 둔다.
6. **체류 시간**: `[IMG: 설명 / alt="키워드 포함"]` 5곳 이상, `[INTERNAL_LINK: 관련 글 주제]` 2곳, 중간에 독자에게 질문 1~2회.
7. **저장·공유**: 체크리스트·비교표·꿀팁 모음을 넣는다.
8. **FAQ**: `## 자주 묻는 질문` 5~7개, 답변 2~3문장. 확인 안 된 내용은 `[확인 필요]`.
9. **마무리**: 한눈에 보는 요약 표 + 댓글 유도 질문 1개 + 저장 권유. 필요하면 `[필자 소개: …]` 칸.
10. **문체**: 친근한 정보형 존댓말, "~입니다" 연속 금지(~예요·~죠·~거든요 혼용), 문단 길이 불규칙, 이모지는 소제목·목록 앞에만.
    네이버 특화 — "최고의", "강력 추천" 같은 상업적 표현 최소화, 이웃 공감 문장 1~2회.
11. 제휴 링크가 들어갈 글이면 제품 언급 지점에 `[AFFILIATE_LINK: 제품명]`, 맨 아래 작은 글씨로 제휴 고지 문구.

출력 순서
1. 원고 본문 (마크다운)
2. `---` 다음 줄에 `태그:` 로 태그 15개를 쉼표로, 그 아래 `참고 자료:` 로 본문에서 실제로 인용한 출처를
   `- 언론사/기관 — 제목 — URL` 형식으로 모두 나열
3. `### SEO 체크리스트` — 메인 키워드 위치별 횟수, 내부 링크 수, 이미지 alt 수, 남은 `[확인 필요]`·`[경험]` 칸 수
````

````text
## AI 영상·이미지 생성 프롬프트 규칙
(OSideMedia/higgsfield-ai-prompt-skill, MIT 의 MCSLA 공식·카메라 용어·네거티브 지침을 요약·번안. Higgsfield·Kling·Seedance·Wan·LTX 등 어느 생성기에나 쓴다)

**쓰는 순서** — 영문 한 문단, 40~120단어(200단어 이하)
`피사체(누가·무엇 + 외형) → 행동(동사 1개 + 강도 부사) → Camera: 이름 붙은 무빙 1개 → 장소·시간대 → Look: 조명·색감·렌즈`
- 장면(컷)당 **주 행동 1개**(보조 1~2개까지), **카메라 무빙 1개**. 반대 무빙을 섞지 않는다(Dolly In + Dolly Out).
- **이미지→영상(I2V)** 은 첫 프레임에 이미 보이는 것을 다시 쓰지 않는다 — "무엇이 움직이는지"와 카메라만.
- 인물을 여러 컷에 이어 쓰면 **외형 블록**(얼굴·헤어·의상·색 — 정적 묘사만)과 **움직임 블록**(동작·카메라만)을 나눠 적는다.
- 비율·길이·해상도는 본문이 아니라 생성기 설정에 둔다(릴스 9:16). 본문에는 프레이밍을 말로: "waist-up medium shot".
- 빠른 동작이 뭉개지면 slow motion으로 만들고 편집에서 배속한다.

**막연한 말 대신 구체적인 말**
| 쓰지 말 것 | 대신 |
|---|---|
| beautiful, stunning, amazing, high quality, 4K | 지운다 — 무엇이 눈에 띄는지 장면으로 |
| cinematic, cinematic lighting | 조명·렌즈 이름: "golden-hour backlight, long shadows", "35mm, shallow depth of field" |
| dynamic, energetic | 동작·무빙으로: "whip pan", "handheld", "leaves swirl across the frame" |
| epic | "towering", "sweeping wide shot" |
| "역동적인 장면" 같은 분위기어 | 물리적 결과: "steam rises from the pot, wind lifts the tent flap" |

- **하지 말 것 대신 원하는 것**을 쓴다(네거티브 입력이 없는 모델이 많다): "no shaky camera" → "locked-off tripod shot",
  "no blur" → "subject in sharp focus, background soft bokeh". 네거티브 칸이 있는 생성기에만 별도로 네거티브를 준다.

**릴스 구간별 카메라 사전**
| 구간 | 추천 무빙 (프롬프트에 이름 그대로) |
|---|---|
| 0~3초 훅 | Crash Zoom In, Super Dolly In, Whip Pan |
| 문제·정보 전달 | static locked-off medium shot, Overhead(음식·책상·준비물), Lazy Susan(제품 한 바퀴) |
| 장소 소개 | Crane Down, Dolly Out, Hyperlapse, Timelapse Landscape |
| 감정·몰입 | slow Dolly In, Handheld, Arc |
| 장면 전환 | Whip Pan, Through Object In, match cut |
| 결과·변화 | Dolly Out reveal, Crane Up |
| 리액션·코미디 | static locked-off (카메라를 멈춰야 타이밍이 산다) |

샷 크기: extreme close-up / close-up / medium / medium full / wide / extreme wide. 앵글: eye level / low angle / high angle / overhead / Dutch angle.

**안전·권리** — 실존 인물·브랜드 로고·방송 화면을 재현하지 않는다. 이미지 안 글자는 `no text, no logo`로 막고 문구는 편집에서 얹는다.
'피해야 할 행동' 이슈는 안전한 모습(올바른 방법)을 보여 준다.

바이럴 포맷 규칙 (채널 "무모한도전") — 정보는 그대로, 보이는 방식을 바꾼다. 사실 규칙이 항상 우선.

- 첫 장·첫 3초 훅은 다섯 유형 중 하나: ① 반전·의외("1위는 의외") ② 손해 회피("이거 모르면 손해") ③ 참견·질문("텐트 안 난로, 괜찮을까?")
  ④ 숫자·랭킹("하지 마세요 TOP 5") ⑤ 직접 해 봤다·비교("3만원 vs 30만원"). 주제를 그대로 제목으로 쓰지 않는다.
- 시리즈 장치: 같은 캐릭터가 같은 형식으로 매번 나온다(예: "명숙 할머니의 잔소리 #3", 꼬북이 리액션). 표지에 시리즈 이름을 넣는다.
- 감정선: 놀람(꼬북이) → 걱정·잔소리(할머니) → 정리(토끼양) → 안심. 한 세트에 캐릭터는 2~3명까지.
- 저장 유도: 체크리스트·요약표 장을 1개 이상, 마무리에 "저장해 두고 ~할 때 꺼내 보세요".
- 댓글 유도: 마지막 장에 고르기 쉬운 질문 하나("여러분은 A파? B파?", "우리 할머니 잔소리 1위는?"). 정답을 아는 척하는 퀴즈 금지.
- 공유 유도: 주제에 맞으면 "○○ 가는 친구한테 보내 주세요" 한 줄(안전·생활 정보와 궁합).
- 하지 않는 것: 사실과 다른 낚시 훅, 공포 조장, 지어낸 수치·후기·경험, 실존 인물 사칭, 위험 행동을 따라 하고 싶게 보이는 연출.
- 사실적인 AI 인물 이미지·목소리를 실제 사람처럼 쓰면 인스타 'AI 정보' 표시를 붙인다(마스코트 인형·합성 음성은 캡션에 "AI 음성" 한 줄).
````

````text
## A. 인스타그램 피드 (제목 수준은 `###`부터)

### 콘텐츠 기획
형식(단일 이미지 / 카드뉴스 8장), 첫 장 훅(14자 안팎), 핵심 메시지 한 문장, CTA(저장 / 공유 / 링크 / 댓글 중 하나)

### 카드뉴스 문구 (장별, 모바일 3줄 이내)
1 첫 장 훅 → 2 문제(타깃의 불편·궁금증) → 3 공감(반복되는 이유) → 4 핵심 정보 → 5 실전 방법·체크리스트 → 6 알면 얻는 것 → 7 주의·확인할 점 → 8 CTA
저장하고 싶은 정보(표·체크리스트)를 한 장 이상.

### 발행용 캡션
첫 문장 훅 → 문제와 공감 → 핵심 정보·방법 → 주의사항·활용 팁 → CTA

### 해시태그 10~15개

### 검수 결과
종합 판정(발행 가능 / 보완 후 발행 / 보완 필요)과 이유 한 줄

### 카드뉴스 데이터 (JSON)
위 카드뉴스 문구를 아래 규칙의 JSON으로도 출력해 줘(그대로 카드 이미지로 굽는다). 피드가 "비추천"이면 생략.

카드뉴스 데이터 규칙 — 피드 카드뉴스 문구를 그대로 PNG로 굽기 위한 JSON (1080×1350, 인스타 캐러셀)

- 장 구성: 8장 안팎(최대 20장). 1 표지(훅) → 2 문제 → 3 공감·흐름 → 4 핵심 정보 → 5 방법·체크리스트(저장용) → 6 얻는 것 → 7 주의 → 8 마무리(CTA).
  한 장에 메시지 하나. 같은 모양이 세 장 넘게 이어지지 않게 화면 칸 종류(rows / list / table / checks / text)를 바꾼다.
- 표지(`cover`): 제목 3줄 이내·줄당 8자 안팎, `*강조*` 한 군데. 화면 칸에 이 세트가 다룰 내용 2~3줄(rows).
- 내지(`page`): `pill`은 장의 역할(예: 왜 궁금할까 / 핵심 정보 / 저장용 / 주의), 제목 2줄·줄당 9자 안팎, 마지막 줄이나 핵심어에 `*강조*`.
- 마무리(`closing`): 공통 CTA 한 문장을 제목으로, 화면 칸에 가져갈 요약(rows 3줄).
- `say`: 카드형 릴스에서 읽을 말 한두 문장(장마다 25자 안팎, 전체 30초 안팎). 카드 글을 그대로 읽지 말고 말하듯 — 예) "텐트 안 난방은 절대 금지예요."
- `desc`는 한 줄(25자 안팎). 화면 칸 글은 줄당 18자 안팎, 3~4줄. 줄을 직접 끊을 땐 `\n`.
- 사실 규칙: 근거는 수집한 기사·영상 제목(과 웹 검색으로 확인한 원문)뿐. 화면 칸 `label`에 근거를 적는다(예: "기사 제목 · 세계일보 10.08").
  확인 못 한 제품명·가격·일정·수치는 `*[확인 필요]*`로 둔다. 예시 화면은 label에 "예시"라고 적는다. 후기·성과·통계를 지어내지 않는다.
- 캐릭터(선택): `host`(덱 최상위)는 진행 캐릭터 id — 릴스의 기본 목소리. 장마다 `speaker`+`line`으로 캐릭터 한마디(20자 안팎)를 넣는다 —
  세트에서 3~4장만, 매 장 넣지 않는다. 한마디가 있는 장은 화면 칸이 낮아지니 화면 칸 글을 3줄(rows·table 3행) 이하로. 이미지가 있는 마스코트는 화면 칸 `character`로 리액션 컷을 쓸 수 있다(표지·반전 장).
  `say`가 있는 장은 그 장의 `speaker` 목소리로 읽힌다. 캐릭터 말투는 아래 명단의 성격을 따른다.
  출연 캐릭터:
  - `kkobuk` 꼬북이 (이미지 있음): 성격 급한 직장인 거북이. 새 소식에 제일 먼저 놀라고 호들갑 떠는 리액션 담당. 반말 섞인 친근한 말투 — "헐, 이거 실화야?", "잠깐만, 나만 몰랐어?"
  - `tokki` 토끼양 (이미지 있음): 차분하고 다정한 정리 담당 토끼. 핵심을 짧게 정리해 주고 저장·댓글을 권한다. 존댓말 — "정리해 드릴게요", "저장해 두세요!"
  - `myeongsuk` 명숙 할머니: 정 많고 잔소리 많은 할머니. 걱정을 잔소리로 표현한다 — "아이고, 그러다 큰일 나!", "밥은 먹고 다니니?" 꾸중보다 다정함이 먼저.
  - `sea` 세아: 직설적이고 쿨한 MZ. 짧고 센 한마디 — "이거 모르면 손해.", "내가 해봤어. 결론부터."
  - `doyun` 도윤: 담백하고 청량한 형/오빠. 직접 해 본 사람처럼 설명 — "제가 직접 비교해 봤어요."
- 화면 칸 종류(`shot`에 하나만): `rows` [["이름","값"], …] · `list` ["줄", …] · `table` [["머리","값"], …] · `checks` ["체크 항목", …] · `text` "문장(*강조* 가능)" · `character` "캐릭터 id" + `mood`(shock/smile) + `bubble` "말풍선".
````

## 공통 원칙 (모든 채널)

1. **주제와 키워드 일관성** — 제목·본문·해시태그·대본에 메인 키워드를 자연스럽게. 채널마다 문체·분량은 다르게, 핵심 메시지와 CTA는 하나로.
2. **사실 규칙 (원천 팁보다 우선)** — 우리 데이터는 기사·영상 **제목**뿐이다.
   - 확인 못 한 수치·날짜·가격·기능·후기는 만들지 않고 `[확인 필요: 무엇을]`.
   - 원천 팁의 EEAT 장치(개인 경험담, 필자 소개, 실제 사례, "23%" 같은 구체 수치)는 **지어내지 않는다.**
     자리만 만들고 `[경험: 직접 겪은 일 한 조각 — 예) 지난 주말 ○○에서]`, `[필자 소개: 전문성 근거]` 처럼 사용자가 채울 칸으로 둔다.
   - 기사 문장을 옮기지 않고 요약 + 출처 링크. 예고편·뮤직비디오·방송 화면은 무단 사용 금지 안내.
3. **민감 이슈** — 개인 건강·정신건강·사생활·진행 중인 논란·사건사고 피해자는 쓰지 않는다(자동 작성 대상이 아님).
4. **AI 티 줄이기** — "결론적으로", "또한", "게다가" 같은 연결어 최소화, "~입니다" 연속 금지(~예요·~죠·~거든요 혼용),
   문단 길이 불규칙, "많은 분들이"·"대부분의 경우" 같은 모호한 표현과 근거 없는 "최고의·가장 좋은" 금지.
5. **광고·제휴** — 협찬·제휴 링크가 들어갈 수 있으면 표기 의무를 상기시키고 고지 문구 자리를 넣는다.
6. **이미지** — 자리만 표시(`[IMG: 설명 / alt="키워드 포함"]`). 실존 인물 얼굴 생성 이미지는 쓰지 않는다.

## 노션 상세 리포트 페이지 구조

이슈 하나의 상세 리포트(목록 페이지의 하위 페이지)는 이 순서로 쓴다. 채널 섹션은 원천 템플릿처럼 색 있는 토글 제목으로.

1. 파란 callout — 검색어·수집 시각·플랫폼별 건수, **콘텐츠 브리프**: 핵심 타깃 / 해결할 문제(독자가 궁금한 것) / 핵심 가치 / 공통 CTA
2. 노란 callout — "수집 데이터는 제목뿐 — `[확인 필요]`·`[경험]` 칸을 채운 뒤 발행"
3. 핵심 이슈 표 (제목=원문 링크, 점수, 플랫폼, 언론사/채널, 날짜) — 리포트 데이터 그대로
4. `# 📝 블로그 {toggle="true" color="blue_bg"}` — references/blog.md
5. `# 🖼️ 인스타그램 피드 {toggle="true" color="pink_bg"}` — references/instagram-feed.md
6. `# 🎬 인스타그램 릴스 {toggle="true" color="red_bg"}` — references/reels.md
7. `# ▶️ 유튜브 {toggle="true" color="purple_bg"}` — references/youtube.md (이슈가 영상화에 안 맞으면 "이 이슈는 유튜브 비추천 — 이유" 한 줄)
8. `🤖 제작 요청 프롬프트` 접힌 블록 — 리포트의 `_요청_blog.txt`, `_요청_reels.txt`, `_요청_channels.txt`(피드+유튜브) 원문을 각각 ```plain text 블록으로
9. 통합 발행 전 체크리스트 (to-do)
   - 모든 채널의 핵심 메시지·CTA가 일치하는가 / 메인·서브 키워드 반영 / 채널별 문체·길이
   - `[확인 필요]`·`[경험]` 칸을 모두 채웠는가 / 사실·링크 검증 / 이미지·영상 권리 확인
10. 🔗 부록 — 수집한 원문 링크(접힌 블록)

각 채널 토글 안에는 원천 템플릿처럼 **검수 결과**(종합 판정: 발행 가능 / 보완 후 발행 / 보완 필요 + 이유 한 줄)를 함께 둔다.
`[확인 필요]`가 남아 있으면 판정은 "보완 후 발행".

## 스타일 업데이트 방법

사용자가 "스타일 업데이트", "작성 팁 바뀌었어" 등을 요청하면:
1. 위 원천 페이지(또는 사용자가 준 새 페이지)를 노션에서 다시 fetch한다.
2. 바뀐 규칙을 해당 references/*.md 에 반영한다. 원천 예시 글을 통째로 옮기지 말고 규칙으로 요약한다.
3. 원천 팁이 위 "사실 규칙"과 충돌하면(경험·수치 지어내기, 상위 노출 확률 같은 근거 없는 예측) 사실 규칙을 유지하고, 바꾼 점을 사용자에게 알린다.
4. 같은 규칙을 웹 LLM 요청 프롬프트·API 모드 지침에도 반영한다 — `agent/prompts/` 의
   system.md(공통 원칙) · blog.md/blog_draft.md(블로그) · reels.md/reels_script.md(릴스) · channels.md(피드+유튜브).
   `{{insight}}`, `{{digest}}`, `{{plan}}` 자리표시는 지우지 않는다. 고친 뒤 `run.bat "아무 키워드" --no-images`로 `_요청_*.txt`가 정상 생성되는지 확인.
5. 바꾼 내용을 사용자에게 요약한다.
